01 / Work

Systems that can explain themselves.

I work across distributed systems and agentic architecture. The common thread is legibility: can the people operating a system see what it did, and why?

At HelloFresh

I'm a Senior Staff Engineer working across a portfolio of teams: target architecture, event-driven services in Go, and the guardrails around non-deterministic systems. That includes human-in-the-loop checkpoints and the boring, important work of making LLM behaviour auditable.

In the open

Most of my public work asks a practical question: can we explain, test, and control what a system actually did? I build local-first tools for that — a runtime that records its actions, an inspector that makes the record queryable, and checks that notice when behaviour changes.

Agenturm Local, terminal-first observability for coding agents. See sessions, tool calls, and traces without a dashboard. Python · MIT ↗ SpanHound MCP tools for reading recorded failures, approvals, token usage, and run comparisons. Python · PyPI ↗ agent-harness A reference runtime with approve/deny/edit gates, budgets, MCP tools, and OpenTelemetry traces. Python · MIT ↗ agent-evals YAML fixtures and trace-backed scorers that turn a failure into a repeatable check. Python · MIT ↗

Also: agent-skills — workflows for trace debugging, HITL policy, MCP authoring, and eval-driven development.

02 / Life

Away from the terminal.

The best software I've made recently wasn't for work.

01 / Home

One very demanding user

A voice-to-spelling app for my kid, and a photo-based app that explains what's good or bad about a food item. Both were built for one person, not a market — and both are better for having no growth team.

Personal software is a good test of craft: no analytics, no engagement loop — just whether it helps one person.

02 / Mountains

Trails and side projects

trekFinder and trek-ai are where a long-standing Himalayan trail habit meets code: a Go API and Postgres, then an early LLM recommender, long before agents were the day job.

03 / Craft

Small on purpose

I like software with a narrow job: local-first, no account, no dashboard, no engagement loop. The best test is whether one person misses it when it's gone.

04 / About

More than the job title.
