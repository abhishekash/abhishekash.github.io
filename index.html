02Open source

All repositories ↗

A connected set of tools for one question: can we explain, test, and control what an agent actually did?

Agent observability · Python

Agenturm

Follow Codex, Claude Code, OpenCode, and Pi from one terminal. Inspect recorded progress, tool calls, and traces, with local storage and no account required for local monitoring.

$uvx agenturm
Try the interactive demo ↗Source ↗PyPI ↗

SpanHound

Trace inspection · MCP

Ask an MCP client about recorded tool failures, approvals, token usage, and run comparisons. Capture supported Python calls, receive local OTLP/HTTP, or read saved JSONL traces.

Try uvx spanhound demo ↗48-second walkthrough ↗

agent-harness

Reference runtime

A tool-using agent runtime with approve/deny/edit gates, bounded execution, MCP tools, and OpenTelemetry traces. The place where execution decisions become inspectable.

Code & quickstart ↗Architecture decisions ↗

agent-evals

Evaluation

YAML task fixtures and trace-backed scorers for tool routing, approvals, budgets, and side effects. The published scripted baseline checks runtime contracts; it is not a live-model reliability score.

Read the evaluation report ↗Task fixtures ↗

agent-skills

Reusable workflows

Focused workflows for trace debugging, approval design, MCP authoring, and eval-driven development, with explicit notes on when each approach works or fails.

Browse the skills ↗

From a blocked command to a regression check

In a scripted regression, the harness blocked cat ../outside.txt, but the trace omitted the returned error. Recording that diagnostic made it queryable in SpanHound and testable in agent-evals. A small example of the tools working together.
