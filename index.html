01 / Selected work

Tools that answer one question.

Can we explain, test, and control what an agent actually did? Each project takes a different part of that question, and they are designed to work together.

Flagship

Agenturm

Know what your agents are doing.

Local, terminal-first observability for Codex, Claude Code, OpenCode, and Pi. Bring recent sessions together, inspect tool calls and MCP evidence, and follow a failure back to its trace — without sending your work to a dashboard.

  • Seven keyboard-first views and five terminal themes.
  • Local SQLite. No account or API key for monitoring.
  • OpenTelemetry ingest for other supported tools.

02 / How it fits

One failed run, four instruments.

The tools grew out of a concrete bug. An agent runtime blocked a shell command that escaped its workspace, but the trace omitted the returned error. Fixing it meant connecting the runtime, the inspector, and a regression test.

  1. 01

    Run it

    A tool-use loop with risk-based approvals, budgets, and bounded execution.

    agent-harness
  2. 02

    Record it

    OpenTelemetry JSONL, or local capture from a supported Python call path.

    OTel / SpanHound
  3. 03

    Inspect it

    Query failures, approvals, token usage, and run differences from an MCP client.

    SpanHound
  4. 04

    Check it

    Score outcome and trace, then fail the build when behaviour regresses.

    agent-evals

The fix shipped in three places. The runtime records the returned error, SpanHound exposes it, and agent-evals fails if it disappears again.
